# 个人配置与状态

本 Skill 的安装包只装通用规则和空白模板。每个用户在其任务工作目录单独保存配置、证据和状态，不共用个人工作历史

## 首次配置

优先从会话读取已确认信息。必要时将问题合成一句：“你的工作范围有哪些，日报希望按什么分类”

| 配置 | 初始处理 |
|---|---|
| 工作范围 | 使用用户的岗位、项目或明确业务目标，无法判断的活动不自行纳入 |
| 分类及顺序 | 使用用户选择；未指定可建议“项目工作、沟通协作、其他”，确认后固定顺序 |
| 时区 | 读取当前环境或用户指定 IANA 时区，不写死地区 |
| 日期范围 | 默认本地今天 00:00 至运行时，用户指定日期优先 |
| 输出位置 | 本任务 outputs 或用户指定目录；内部状态放 work/workday-report-summary-assistant |
| 模板 | 默认 assets/report-template.xlsx；用户改版后以最新确认版为准 |
| 定时 | 默认未设置；用户要求后再明确时间及工作日范围 |
| 文案 | 跟随用户语言，默认每项一句、句末不加句号 |

记录在 `profile.json` 中的最小示意：

```json
{
  "schema_version": 1,
  "work_scope": ["由当前用户确认的工作范围"],
  "timezone": "由当前环境确认的 IANA 时区",
  "category_order": ["项目工作", "沟通协作", "其他"],
  "template": "使用者确认的模板文件",
  "schedule": null
}
```

这里的文字说明不是可执行占位配置，不应照抄为已确认值。首次只保存已知项，其他信息按需要补充

## 证据记录

在任务工作目录保存简短证据表或 JSON，至少包括本地日期、项目、所观察动作、来源引用、来源时间、能支持的结论。引用可以是文件名、事件时间、消息或任务标识，不复制完整私人聊天

电脑历史主要用于发现工作，直接来源和用户明确确认用于判断成果。没有直接来源时保留有证据的动作级描述

## 跟进节点

用项目的稳定标识和节点名维护 `followups.json`，只记录：

- `project_id`、`milestone`：例如同一项目分别跟踪“提交”“反馈”，不合并为模糊的“完成”
- `last_confirmed_status`、`confirmed_at`、`evidence_date`、`source_ref`：上次被确认的内容和时间
- `last_asked_at`、`next_check_date`：避免重复询问的依据

未知值用 null，不凭空补时间；用户已确认完成的节点不再询问。上次状态属于历史事实，新的确认只更新对应节点，不把其他节点一并标记完成

## 日报归档

生成脚本保存独立的 ledger JSON，供下一次合并。一个日期中的每项工作有稳定 `id`，同一天再次出现相同 id 更新该行，其他项目保留；跨日期相同 id 可用于同一个项目，不代表延续上一天的完成状态

每次生成保留新的 ledger 文件和工作簿，不覆盖上次已验证归档。只有新一对文件检查通过后，才更新本地“最新版本”指针。若用户改过 Excel，以实际工作簿和用户最新反馈校正 JSON 后再生成；不得丢弃其手工修改

不要把本用户的 profile、ledger、followups 或真实证据打包到分享版 Skill
